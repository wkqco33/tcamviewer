# 성능 최적화 심층 분석 (Performance Optimization)

`tcamviewer`가 터미널 환경에서 깜빡임 없이 초당 수만 프레임의 연산 속도를 달성할 수 있는 핵심 알고리즘과 최적화 기법을 설명합니다.

---

## 1. Half-Block TrueColor 렌더링 원리

터미널 글꼴의 가로:세로 비율은 일반적으로 약 **1:2**입니다. 일반적인 사각형 블록 문자를 출력하면 세로로 길게 늘어지는 왜곡이 발생합니다.
- 유니코드 상단 반쪽 블록 문자 **`▀` (U+2580, `\xE2\x96\x80`)**을 사용합니다.
- **전경색(Foreground)**: 상단 픽셀 색상 (`\x1b[38;2;R;G;B;m`)
- **배경색(Background)**: 하단 픽셀 색상 (`\x1b[48;2;R;G;B;m`)
- 결과적으로 문자 셀 1개(1:2 비율)에 상/하 2개의 픽셀이 들어가므로, **1:1 종횡비**의 정사각형 픽셀 그리드가 완성됩니다.
- 예: 80×24 크기의 터미널 창 → 실제 해상도 **80×48 픽셀**로 비디오 표현.

---

## 2. Dirty-Diff 캐시 최적화

초당 30~60프레임 동안 전체 터미널 화면을 매번 지우고(`\x1b[2J`) 수만 개의 ANSI 코드를 전송하면, 터미널 에뮬레이터의 I/O 병목으로 인해 심각한 프레임 드랍과 깜빡임(Flicker)이 발생합니다.

- **셀 단위 비교**: 이전 프레임 그리드(`prevGrid_`)와 현재 프레임 그리드(`currGrid_`)를 셀 단위로 비교합니다.
- **국소 갱신 모드 (변경율 < 40%)**:
  - 변경된 셀의 위치로만 커서를 직접 이동(`\x1b[Row;ColH`)하여 변경된 블록만 출력합니다.
- **전체 순차 갱신 모드 (변경율 >= 40%)**:
  - 커서를 좌상단 홈(`\x1b[H`)으로 이동한 뒤 순차 출력하되, 인접 셀의 전경/배경색이 동일하면 중복 ANSI 색상 코드를 생략합니다.
- 결과적으로 **터미널 출력 I/O 데이터를 70% 이상 절감**합니다.

---

## 3. Zero-Allocation 인라인 포맷터

C++의 `std::to_string` 및 `std::string`의 문자열 결합(`+`) 연산은 매번 힙 메모리 할당(`malloc`/`free`)을 수반합니다. 8,000개의 셀을 렌더링할 때 프레임당 수만 번의 힙 할당이 발생하면 CPU 캐시가 오염되고 성능이 급격히 저하됩니다.

- **인라인 10진수 스트리밍**:
  - 0~255 범위의 `uint8_t` 값을 나눗셈 몇 번으로 분해하여 `outputBuffer_`에 직접 `char` 단위로 푸시합니다.
- **Zero-Allocation**:
  - ANSI 시퀀스 생성 중 힙 할당이 완전히 배제되어 프레임당 동적 메모리 할당 0회를 달성했습니다.

---

## 4. 64비트 단일 레지스터 셀 비교

- `CellColor` 구조체(RGB 6바이트)를 `alignas(8)` 8바이트 정렬했습니다.
- 두 셀을 비교할 때 6개 필드를 개별 `&&` 연산하지 않고, 단 1회의 64비트 정수 레지스터 비교(`uint64_t`)로 처리합니다.
- CPU 레지스터 레벨에서 단 1 클럭 사이클에 셀 변경 여부를 감지합니다.

---

## 5. 가로축 좌표 변환 사전계산 (X-LUT)

- 비디오 다운스케일링 시 수평 픽셀 좌표 계산(`(c * effW) / renderCols`)을 이중 루프 내부에서 매번 수행하던 것을, 행 밖에서 1차원 테이블(`eff_x_lut`)로 사전 계산했습니다.
- 내부 루프의 정수 나눗셈 연산과 회전(`rot`) 분기 예측 실패가 완전히 제거되었습니다.

[`tests/test_renderer.cpp`](tests/test_renderer.cpp)의 `BenchmarkPerformance` 검증 결과:
- **환경**: 160×50 터미널 (8,000 셀, 160×100 픽셀)
- **입력**: 640×360 영상 100프레임 연속 렌더링
- **소요 시간**: **단 3ms** (프레임당 0.03ms 소요, **초당 30,000+ FPS 처리 성능**)
